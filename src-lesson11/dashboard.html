Two independent objects, so the pill shows both — the same
      connector/task pair preflight.py prints. The connector is the
      configuration the worker owns; the task is the thread actually reading the WAL.
      A RUNNING connector whose task has FAILED publishes nothing —
      the exact shape of a green dashboard that is lying to you.

      ⑤
ClickHouse — every version, then the winner

      
      idle
      
    

    
Same table, twice. Without FINAL you see every version that ever
      arrived, including replays. With FINAL the highest version (the Debezium
      LSN) wins. Neither query filters _is_deleted — the API does that, so a deleted
      canary is visible here as an orange tombstone row that outranks its
      own history. Fewer rows than you wrote is not loss: ReplacingMergeTree
      merges in the background, so an order's older versions disappear on their own
      once the winner is settled.
